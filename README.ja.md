# Reverse-Proxy WAF

日本語 | [English](README.md)

Web アプリの手前に置く**リバースプロキシ型の WAF(Web Application Firewall)**です。Python の標準ライブラリだけで動き、管理ダッシュボードと攻撃マップを内蔵しています。

リクエストを検査し、XSS・SQL インジェクション・パストラバーサル・コマンドインジェクションなどの攻撃を、バックエンドに届く前に遮断(または記録のみ)します。

```
ブラウザ ──► [ WAF :8080 ] ──検査──► バックエンドのアプリ
                 │   └─► ログ ──► [ ダッシュボード :8090 ](同一プロセス・攻撃マップ)
                 ├─ 危険 → 403 で遮断(block モード)/ ログのみ(detect モード)
                 └─ 応答に CSP などのセキュリティヘッダを付与
```

> **バックエンドのアプリは付属していません。**
> このリポジトリに入っているのは WAF とダッシュボードだけです。同梱の設定は `https://127.0.0.1:5000` を転送先にしています。これは作者が動作確認に使った Stored XSS のデモ用掲示板アプリが動いていたポートで、そのアプリはこのリポジトリに**含まれていません**。転送先のアプリは各自で用意してください([クイックスタート](#クイックスタート)を参照)。

> 教育と、許可を得た検証環境でのみ使ってください。自分のものでないシステムや、許可のないシステムには使わないでください。

## 主な機能

- **リクエスト検査**: URL・クエリ・ヘッダ・ボディ・Cookie を多段デコードして、15 カテゴリ・約 100 のルールで検査します(XSS、SQLi、パストラバーサル、コマンドインジェクション、SSRF、XXE、SSTI、NoSQLi、LDAP、CRLF、オープンリダイレクト、アップロード、スキャナー、デシリアライズなど)。ルールごとに「遮断 / 検知のみ / 使わない」を選べます。
- **応答の検査**: バックエンドが返す HTML の中の攻撃スクリプト(Stored XSS)を無害化または遮断します。
- **DoS・不正接続対策**: レート制限、同時接続の上限、Slowloris / Slow POST の締め切り、ボディの上限、リクエストスマグリング対策、繰り返す攻撃元の自動 BAN。
- **IP・国の制御**: 手動 BAN、許可リスト、除外 IP、国の許可 / ブロック(オフライン GeoIP にも対応)。
- **複数バックエンドの同時防御**: 専用ポート、ホスト名、パスで振り分けます。バックエンドごとにモード、ルール、IP 制御、稼働監視を持ちます。
- **ダッシュボード**: ホーム、トラフィック、リアルタイムと集計の攻撃マップ、Burp 風の詳細表示つきイベントログ、状態ログ、IP 管理、ルール管理。
- **攻撃アラート**: 攻撃を検知すると、警報バナーと六角形の「EMERGENCY」背景で知らせます。
- **ユーザー・組織・権限**: 管理者 / アナリスト / 一般 / キー・オフィサーの役割、担当範囲つきの組織の木、ログのマスク、申請(チケット)の流れ。
- **ログの扱い**: バックエンドごとの日次ログ、保存期間、書き出し、組織ごとの公開鍵によるログ詳細の暗号化(任意)。
- **外部連携**: Webhook 通知、申請のメール通知、nginx など別の逆プロキシの背後での運用。

## 動作環境

- Python 3.8 以降(静的な確認では、それより新しい構文や標準ライブラリは使っていません。動作確認は 3.13 と 3.14)
- 外部パッケージは不要です。
- 任意: `cryptography`(自己署名証明書の生成とログ詳細の暗号化。証明書は `openssl` コマンドでも代用できます)、`python-geoip-geolite2`(オフラインの国判定)

## クイックスタート

1. 転送先となる Web アプリを何でもよいので起動します。試すだけなら HTTP で構いません。

   ```bash
   mkdir site && cd site
   echo "<h1>hello backend</h1>" > index.html
   python3 -m http.server 5000
   ```

2. 別のターミナルで、リポジトリの直下から WAF を起動し、そのバックエンドを指定します。

   ```bash
   python3 waf.py --backend http://127.0.0.1:5000 --no-listen-tls
   ```

3. バックエンドではなく、WAF のアドレスにアクセスします。

   - `http://127.0.0.1:8080/` はそのままバックエンドに渡ります。
   - `http://127.0.0.1:8080/?q=<script>alert(1)</script>` は `403` で遮断されます。

4. ダッシュボードは `https://127.0.0.1:8090` です。自己署名証明書なので、ブラウザが一度警告を出します。

`--no-listen-tls` を付けない場合、WAF は HTTPS で待ち受けます。`data/waf_cert.pem` と `data/waf_key.pem` がなければ、自己署名証明書を自動で作ります。

同梱の設定のまま使う場合(8081〜8084 の 4 つのサンプルバックエンドが、すべて `https://127.0.0.1:5000` に転送する設定)は、5000 番で HTTPS のアプリを動かすか、`config/waf_config.json` またはダッシュボードの「設定 → バックエンド」で転送先を書き換えてください。

### よく使うオプション

```bash
python3 waf.py --mode detect                       # 遮断せず記録だけ(最初の動作確認向き)
python3 waf.py --mode block                        # 遮断モード
python3 waf.py --site shop=8081=https://192.168.0.10:5000 --site blog=8082=http://192.168.0.20:3000
python3 waf.py --path-route /shop=https://192.168.0.10:5000 --path-route /blog=http://192.168.0.20:3000
python3 waf.py --allow-country JP --block-ip 203.0.113.0/24
python3 waf.py --help                              # そのほかすべて
```

## ポート

| ポート | 用途 | 備考 |
|---|---|---|
| 8080 | WAF | 既定は HTTPS |
| 8081〜8084 | バックエンドごとの WAF ポート | サンプル設定の 4 つのバックエンド用 |
| 8090 | ダッシュボード | HTTPS、ログイン必須 |
| 127.0.0.1:8099 | ルール管理ツール | `start_rules_tool.bat` で起動 |

## ダッシュボードのログイン

サンプル設定の `dashboard.users` には `admin`、`soc`、`ko` などのユーザーがいますが、パスワードは公開していません。`password_hash` を自分のものに入れ替えてください。リポジトリの直下で次を実行します。

```bash
python3 -c "import sys; sys.path.insert(0,'src'); import waf_extras as w; print(w.hash_password('パスワード'))"
```

出力された文字列を、`config/waf_config.json` の該当ユーザーの `password_hash` に貼り付けます。`dashboard.users` を空にすると、共通の単一パスワード(`dashboard.password`)方式に戻ります。

## サンプルの鍵と設定について

- `秘密鍵/` と `data/waf_key.pem` には、ログ暗号化の流れを試せるように、あえて公開している**デモ用の鍵**が入っています。誰でも読めるので、実データには絶対に使わず、実運用では必ず自分で鍵を作り直してください。
- サンプル設定では `enc_demo_keys` が `true` です。実運用では切ってください。
- サンプル設定のダッシュボードは `0.0.0.0` で待ち受けます。ネットワークから見せたくなければ、`dashboard.host` を `127.0.0.1` にしてください。
- `log_pass_body` が `true` で、通過したリクエストのボディも記録します。認証情報の扱いに注意してください。

## 構成

```
waf.py                  本体。プロキシとダッシュボードを 1 プロセスで起動
start_rules_tool.bat    ルール管理ツールの起動(Windows)
src/                    部品と同梱の世界地図
config/                 waf_config.json(追加ルールを作ると custom_rules.json も)
data/                   実行時のデータ(ログ・申請・操作記録・証明書)
tests/                  テスト
docs/README.md          詳細ドキュメント(日本語)
```

全設定項目、ダッシュボードの各画面、ログ暗号化、キー・オフィサーの流れなどは、[docs/README.md](docs/README.md) に詳しく書いてあります。

## 限界

署名ベースの WAF は多層防御の一層であり、脆弱なコードの根本対策ではありません。未知の攻撃や高度に難読化された攻撃をすべて防げるわけではないので、アプリ側の修正(出力のエスケープ、サニタイズ、CSP)も続けてください。
